## Asking a question

If the documentation does not answer your question, please open a
[GitHub Discussion](https://github.com/minifyjs/minifyjs/discussions)
rather than an issue. Discussions are the right place for:

- "How do I...?" questions
- Configuration help
- Ideas that are not yet concrete enough for a feature request

## Reporting a bug

If you believe you have found a bug, open an issue using the
**Bug report** template. Include:

- MinifyJS version (`minifyjs --version`)
- Operating system and architecture
- A minimal reproduction
- Actual output vs. expected output

## Requesting a feature

If you have a concrete feature request, open an issue using the
**Feature request** template. Explain the problem you are trying to
solve, not just the solution you have in mind.

Before opening a feature request, please read
[CONTRIBUTING.md](CONTRIBUTING.md), which explains what kinds of
features are in scope. MinifyJS is deliberately small; the fastest
way to get a feature accepted is to describe a real problem and let
the maintainers propose a fix.

## Security issues

Do not open a public issue for security problems. See
[SECURITY.md](SECURITY.md).

## Commercial support

There is no commercial support for MinifyJS. It is a volunteer
project. If you need a guaranteed response time or a support
contract, we recommend using [esbuild](https://esbuild.github.io/)
directly, which has paid support options through its maintainer.

## Response time

This is a volunteer project. We aim to respond to issues and
discussions within one week, but there is no guarantee. If a week
has passed without a response, it is fine to leave a comment
reminding the maintainers.
